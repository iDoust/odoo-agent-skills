# Odoo 19

## Verified guidance

- Inspect the Odoo 19 source before applying a migration recipe. The ORM
  source is reorganized under `odoo/orm/` (23 files), so paths and
  implementation details should not be assumed from earlier versions.
- Odoo 19 core defines table constraints through `models.Constraint` and warns
  about the older `_sql_constraints` model attribute. Migrate only the models
  affected by the target project and test module installation or upgrade.
- Use the supported SQL API from the target source for queries that cannot be
  expressed through the ORM; keep identifiers controlled and values
  parameterized.
- View modifiers remain Python-expression based, but the available values and
  view schemas are version-specific. Validate the final XML against Odoo 19.
- Controller routes now use `type='jsonrpc'`; `type='json'` no longer exists
  in the Odoo 19 source (0 occurrences verified).

## ORM restructure

In Odoo 19, the monolithic `odoo/models.py` is split into `odoo/orm/`:

```
odoo/orm/
├── models.py              # BaseModel, Model, TransientModel
├── models_transient.py    # TransientModel specifics
├── fields.py              # Field base class
├── fields_binary.py       # Binary, Image
├── fields_misc.py         # Boolean, Html, Json, Properties
├── fields_numeric.py      # Integer, Float, Monetary
├── fields_reference.py    # Reference
├── fields_relational.py   # Many2one, One2many, Many2many
├── fields_selection.py    # Selection
├── fields_temporal.py     # Date, Datetime
├── fields_textual.py      # Char, Text
├── domains.py             # Domain, DomainBool classes
├── decorators.py          # api.model, api.depends, api.private, etc.
├── environments.py        # Environment
├── identifiers.py         # NewId, etc.
├── model_classes.py       # MetaModel, model setup
├── registry.py            # Registry
├── table_objects.py       # Constraint, Index
├── types.py               # Command, etc.
├── utils.py               # Internal utilities
└── commands.py            # CLI commands
```

Public imports (`from odoo import models, fields, api`) still work. Code that
imports internal ORM paths directly may break.

## Breaking changes introduced in Odoo 19.x

### 19.0

- `odoo.osv` module deprecated with deprecation warning:
  `"Since 19.0, odoo.osv is deprecated use odoo.fields.Domain"`.
  Use `odoo.fields.Domain` or `from odoo.orm.domains import Domain` instead.
  [#217708](https://github.com/odoo/odoo/pull/217708)
- `record._cr`, `record._context`, `record._uid` deprecated. Use
  `record.env.cr`, `record.env.context`, `record.env.uid` instead.
  [#193636](https://github.com/odoo/odoo/pull/193636)

  ```python
  # Before
  self._cr.execute(query)
  ctx = self._context

  # After
  self.env.cr.execute(query)
  ctx = self.env.context
  ```
- `GROUPING SETS` support added for pivot views via `_read_grouping_sets`.
  [#194413](https://github.com/odoo/odoo/pull/194413)
- Dynamic dates in domains.
  [#216665](https://github.com/odoo/odoo/pull/216665)
- **Native Row Locking (`lock_for_update` & `try_lock_for_update`)**:
  Eliminates manual `cr.execute("SELECT ... FOR UPDATE")` raw queries:
  - `records.lock_for_update(allow_referencing=False)`: Acquires an exclusive write lock; raises `LockError` if records are locked.
  - `records.try_lock_for_update(limit=10)`: Skips locked rows (`FOR UPDATE SKIP LOCKED`) and returns the subset of records successfully locked—ideal for concurrent background workers and payment queues.
- **Environment Timezone (`self.env.tz`)**:
  `Environment` now provides `self.env.tz` directly, returning a `pytz` tzinfo object resolved from `self.context.get('tz')` or `self.user.tz` (falling back to UTC) without manual boilerplate.
- `account.account` gained `expense_other` ("Other Expenses") in `account_type` selection, enabling clean statutory separation of operating overheads from non-operating expenses and financial charges.

### Inherited from 18.x (applies to v19)

All 18.x changes carry forward. The most impactful for migration:
- `type='json'` → `type='jsonrpc'` (introduced 18.1, enforced 19.0: zero
  `type='json'` occurrences remain in v19 source)
- `read_group` deprecated → use `_read_group` / `formatted_read_group`
- `@api.private` for non-RPC methods
- `models.Constraint` replaces `_sql_constraints`
- Demo data not loaded by default

## Upgrade focus

For 18 to 19 upgrades, inspect constraints, ORM imports and signatures, SQL,
frontend modules, assets, controllers, and security behavior. Avoid declaring
type annotations or frontend changes mandatory without checking the actual
target API and project code path.

Key migration checks:
- Replace `self._cr` / `self._context` / `self._uid` with `self.env.cr` /
  `self.env.context` / `self.env.uid`.
- Replace any `from odoo.osv import expression` with
  `from odoo.fields import Domain` (using `Domain.AND`, `Domain.OR`, or `&`, `|`, `~`).
- Leverage Odoo 19 External JSON-2 API (`/json/2/...` with Bearer auth) for modern integrations instead of legacy XML-RPC/JSON-RPC.
- Annotate read-only ORM methods with `@api.readonly` to take advantage of automatic read-only cursor routing on multi-replica PostgreSQL clusters.
- Verify all internal ORM imports still resolve after the `odoo/orm/` split.
- Confirm `type='jsonrpc'` on all custom controller routes (no `type='json'`).
- Replace `_sql_constraints` with `models.Constraint` attributes.
- Test module install/upgrade after constraint migration.
