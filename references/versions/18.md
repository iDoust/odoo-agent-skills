# Odoo 18

## Verified guidance

- Start from the shared 17–19 baseline and inspect the Odoo 18 source for the
  exact behavior used by the module.
- Distinguish between **Odoo 18.0 LTS** (on-premise release) and intermediate
  **SaaS releases (18.1–18.4)** whose changes are finalized in Odoo 19.
- Do not treat `_check_company_auto`, `check_company`, or the SQL wrapper as
  features introduced only in Odoo 18; those mechanisms are already present in
  Odoo 17 core.
- View architecture: Root `<tree>` tag is renamed to `<list>`. In Odoo 18,
  views use `<list>...</list>` and `ir.ui.view.type` is `'list'`.
- ORM lives in `odoo/models.py` (single file), same layout as Odoo 17.

## Breaking changes in Odoo 18.0 LTS

The following changes apply directly to the Odoo 18.0 LTS on-premise baseline:

### Views: `<tree>` renamed to `<list>`

- The root tag for list views in XML changed from `<tree>` to `<list>`.
- `view_mode` conventions prefer `'list,form'` over `'tree,form'`.
- **XPath impact**: Inheriting views must target `//list` instead of `//tree`.
  Existing `<xpath expr="//tree" ...>` will fail to match on Odoo 18 parent views.

```xml
<!-- Before (v17) -->
<record id="view_my_model_tree" model="ir.ui.view">
    <field name="name">my.model.tree</field>
    <field name="model">my.model</field>
    <field name="arch" type="xml">
        <tree string="My Models">
            <field name="name"/>
        </tree>
    </field>
</record>

<!-- After (v18+) -->
<record id="view_my_model_list" model="ir.ui.view">
    <field name="name">my.model.list</field>
    <field name="model">my.model</field>
    <field name="arch" type="xml">
        <list string="My Models">
            <field name="name"/>
        </list>
    </field>
</record>
```

### Model name search: `_search_display_name` replaces `_name_search`

- Override `_search_display_name` instead of `name_search` or `_name_search`.
  [#174967](https://github.com/odoo/odoo/pull/174967)

```python
# Before (v17)
@api.model
def _name_search(self, name, domain=None, operator='ilike', limit=100, order=None):
    domain = [('code', operator, name)] + (domain or [])
    return self._search(domain, limit=limit, order=order)

# After (v18+)
def _search_display_name(self, operator, value):
    return ['|', ('name', operator, value), ('code', operator, value)]
```

### Access checks: Unified `check_access`, `has_access`, `_filtered_access`

- New methods check both model access rights (ACL) and record rules in a single call.
  [#179148](https://github.com/odoo/odoo/pull/179148)

```python
# v18+ — check access rights + record rules in one call
records.check_access('write')
if records.has_access('unlink'):
    records.unlink()
accessible = records._filtered_access('read')
```

### `@api.private` and `@api.readonly` decorators

- `@api.private`: Distinguishes internal Python methods from RPC-callable methods.
  [#195402](https://github.com/odoo/odoo/pull/195402)
- `@api.readonly`: Marks methods that can be routed to a read-only PostgreSQL replica cursor during RPC calls.

```python
@api.private
def _internal_calculation(self):
    ...

@api.readonly
def get_dashboard_metrics(self):
    return {
        'order_count': self.search_count([]),
    }
```

### Direct SQL Execution with Auto-Flush (`self.env.execute_query`)

- In Odoo 18+, `Environment` provides `execute_query(query: SQL)` and `execute_query_dict(query: SQL)`.
- Automatically calls `self.flush_query(query)` to flush all fields referenced in the query metadata before execution, eliminating manual `flush_all()` boilerplate and stale SQL reads.

```python
from odoo.tools import SQL

# Returns list of tuples with automatic dirty-field flushing
rows = self.env.execute_query(SQL(
    "SELECT id, price_unit FROM sale_order_line WHERE order_id = %s", self.id
))

# Returns list of dicts
partner_dicts = self.env.execute_query_dict(SQL(
    "SELECT id, name FROM res_partner WHERE active = %s", True
))
```

### Translations on `Environment`

- Translations can be resolved directly via `self.env._(...)`.
  [#174844](https://github.com/odoo/odoo/pull/174844)

### Products: `detailed_type` removed, `is_storable` boolean introduced

- In Odoo 17, storable products were defined by `detailed_type = 'product'`.
- In Odoo 18+, `detailed_type` was completely removed. The `type` selection field
  is simplified to `[('consu', 'Goods'), ('service', 'Service'), ('combo', 'Combo')]`.
- Tracking inventory on hand is now governed by the boolean field `is_storable`
  (provided by `addons/stock` on `product.template` and `product.product`).
- **Migration & Search impact**:
  - Replace `('detailed_type', '=', 'product')` or `('type', '=', 'product')` with
    `('is_storable', '=', True)`.
  - When creating storable products in v18+: set `'is_storable': True`.

## Note on SaaS 18.x changes (enforced in Odoo 19)

Features introduced in intermediate SaaS releases (18.1–18.4) for Odoo Online
landed as standard in Odoo 19.0. On standard **Odoo 18.0 LTS**:
- **Controllers**: Keep using `type='json'`. `type='jsonrpc'` is not recognized
  by the 18.0 dispatcher and raises `KeyError`.
- **Model constraints**: Keep using `_sql_constraints = [...]`. The
  `models.Constraint` class is not available in 18.0 LTS.
- **Domains**: Continue using domain lists and `odoo.osv.expression`. The
  `Domain` class is introduced in Odoo 19.

## Upgrade focus (17 → 18)

When upgrading a module from Odoo 17 to Odoo 18:
- Replace `<tree>` with `<list>` in list views and update inherited view XPaths
  (`//tree` → `//list`).
- Replace `_name_search` overrides with `_search_display_name`.
- Replace `('detailed_type', '=', 'product')` searches with `('is_storable', '=', True)`.
- Use `check_access` / `has_access` for unified permission checks.
- Add `@api.private` on internal helper methods that should not be exposed to RPC.
- In list views, use `column_invisible` for table column visibility.
- Keep `type='json'` for controllers targeting 18.0 LTS.
- Keep `_sql_constraints` for models targeting 18.0 LTS.
- Validate view modifiers, multi-company rules, and test suites.
